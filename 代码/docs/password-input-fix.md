# 密码输入异常修复版

修改前回退基线：`4042f35`。

## 修改内容

- Classic / Math 输入满七位后校验，不再继续扫描并修改密码 50000 次。输入函数使用主循环的同一份按键结果，避免模式切换与密码输入读取到不同按键。
- 键盘每行等待 50 微秒后一次性读取输入；拒绝多键不确定结果。按下和松开均需跨 15 毫秒的稳定采样；未确认松开之前不能变成另一按键。连续两个 5 需要正常松手再按。
- 初始化 AFIO 时钟并关闭 JTAG、保留 SWD，释放 PB4。扫描行改为开漏输出，未选中行释放，避免多键按下时推挽输出互相驱动。
- LCD 仅写 PA0～PA7，初始化也仅修改 LCD 引脚，不再把 PA8 / PA10 清零。PA10 因此会保持游戏逻辑要求的电平；外接继电器/负载的实际持续动作需要实机确认。
- LCD 改为只写总线，普通操作间隔 50 微秒，清屏/归位等待 2 毫秒，E 脉冲保持 1 微秒；取消无超时忙等待及读取时的数据总线争用。
- 中断共享变量 Num 和对应 extern 声明改为 volatile。
- 上电第一行居中显示 CSJOYER.COM 约一秒，第二行留空，不再显示 BOOT/RST。内部仍保存 g_bootResetFlags，可通过调试器读取。
- 拆包成功时先关闭倒计时蜂鸣器，成功提示的五次翻转结束后再次明确关闭。旧逻辑遗漏关闭，原先被 LCD 整端口清零掩盖；修复覆盖三个模式共用的成功状态。
- Classic、Math、Hold 共用的超时状态不再主动开启蜂鸣器持续 4 秒；进入时关闭蜂鸣器，显示 T win! 并发送一次爆炸音乐指令。保留原来的 4 秒后 PA10 关闭动作，暂未确认该引脚的实际负载。4 秒不是歌曲播放完成检测；代码未发送停止播放或软件复位命令。用户观察到 BOOT 再现的原因仍待 RST 数值及 PA10 接线确认，不能视为已经修复。

## 构建与交付

`Objects/fixed/c4-fixed.bin`：烧录起始地址 `0x08000000`。

使用现有 Keil ARMCC 5 工具链，按工程文件重新编译全部 C 文件、汇编启动文件并链接，不混用旧目标文件。编译及链接成功；剩余 6 条警告来自原有文件缺少末尾换行和未使用的 lockFlash 函数。没有连接故障板，未做实机功能、按键电气时序及长期断电测试。

Keil 用户可直接打开 Project.uvprojx，执行 Rebuild All 后烧录；现有 After Build 导出配置保持不变。
