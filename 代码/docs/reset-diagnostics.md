# 密码输入异常：启动诊断版

当前版本已按品牌展示需求改为显示 CSJOYER.COM，不再显示 BOOT/RST，也不再使用 RESET_DIAGNOSTICS 开关。内部 g_bootResetFlags 记录仍保留。以下为旧诊断版的历史说明。

后续已加入稳定性修复；当前版本与固件位置请参阅 [修复说明](password-input-fix.md)。本文以下内容记录之前的纯诊断版，不代表当前源码只包含诊断改动。

修改前备份：`4042f35`，已推送到 origin/main。

本轮只增加启动诊断，保留密码扫描、LCD 驱动和游戏流程，尚未修复疑似根因。

## 操作

1. 在 Keil 中重新编译工程并烧录，或使用 `Objects/c4-diagnostics.bin`（起始地址 `0x08000000`）。这个单独的诊断文件使用新编译的 main 和已有其他目标文件链接生成；正式交付前建议在 Keil 中 Rebuild All。
2. 断开 ST-Link，使用原来的独立电源测试，建议录像。
3. 正常启动时第一行显示 `BOOT`，第二行显示 `RST=xxxxxxxx`，持续约一秒，然后进入原界面。
4. 在故障板 Classic、Math 模式输入 7355608，记录异常后是否再次出现 BOOT，以及新的 RST 数值；对比 Hold 模式。

再次出现 BOOT 表示程序重新执行了启动诊断；没有 BOOT 时，不能仅凭七个星号判定复位。若 LCD 本身异常，标记也可能无法显示，需要结合调试器或复位引脚测量确认。

## 复位标志

`g_bootResetFlags` 在 main 入口保存 RCC->CSR，随后清除硬件复位标志，避免以前的标志一直累积。它只保留本次启动的快照，不是跨断电历史记录。显示为完整 CSR 十六进制值，须按位判断，可同时存在多个标志。

| 掩码 | 含义 |
| --- | --- |
| 0x04000000 | PINRSTF：复位引脚标志；不能单独断定外部干扰 |
| 0x08000000 | PORRSTF：上电/掉电复位标志 |
| 0x10000000 | SFTRSTF：软件复位 |
| 0x20000000 | IWDGRSTF：独立看门狗复位 |
| 0x40000000 | WWDGRSTF：窗口看门狗复位 |
| 0x80000000 | LPWRRSTF：低功耗复位 |

不要使用现有 printf 输出诊断文字：它与 MP3 共用 USART1。诊断显示利用原有一秒启动等待，不额外延长该等待；但额外 LCD 写入仍可能影响故障时序，诊断版不再复现也不代表修复。

完成排查后，将 main.c 中 RESET_DIAGNOSTICS 设为 0 可关闭启动画面。原 MP3 硬件测试入口已移除。
